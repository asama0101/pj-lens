# SPEC: ネットワーク設備プロジェクト管理ダッシュボード

## 概要

### 目的とゴール
ネットワーク設備の管理者（利用者は自分のみ）が、増設・更改・改善・不具合対処など複数のプロジェクトを**ダッシュボード1つで俯瞰**し、外部要因による日程変更の見直しと、今日やるタスクの判断を **Claude Code のサブエージェントに支援させる**。進捗共有は HTML／PDF のレポートで済ませる。

完了の判定基準は「受入条件」を参照。

### 入力
- 依頼文の要約: NW 設備管理者向けのプロジェクト進捗・個人タスク管理ツール。ダッシュボード一元管理＋Claude Code サブエージェント支援。困りごとは、(1) 外部要因（ベンダー・社内部署）で日程が動いたときの見直しが大変、(2) 自分が何をやるか常に考える負担、(3) 複数プロジェクトを俯瞰できない、(4) 会議で時間が埋まり優先順位が不明、(5) 進捗共有が面倒。
- 入力ファイル: なし（依頼文は `request.md`）

### 構成（確定）
- **データの正本**: 1つの JSON ファイル（プロジェクト・タスク・先行関係・待ち先・変更履歴・予定のキャッシュ）。サーバー、SQLite は使わない。
- **ダッシュボード**: 静的 HTML 1ファイル。Edge/Chrome のファイル書込み許可（File System Access API）で JSON を読み書きし、画面から編集・保存する。「更新」ボタンで再読込（Claude Code が更新した内容の反映）。
- **サブエージェント（`.claude/agents/`）**: replan／daily-planner／intake の3つ。JSON を読み書きする。
- **レポート**: サブエージェントではなく**スクリプト1つ**。JSON から HTML を出力し、Edge のヘッドレス印刷で PDF にする。
- **動作環境**: Windows PC のみ、利用者は自分のみ。MCP はツールに**同梱しない**（利用者が別途導入、導入手順は README に記載）。

## 流れ

1. **日常の更新**: Claude Code に自然文で伝える（「ベンダーXの納品が2週間遅れた」）か、ダッシュボード画面で直接編集する。
2. **日程変更の見直し（replan）**: 変更を受け、先行関係をたどって影響範囲を洗い出し、日程変更案と理由を提示する。承認後に JSON を更新し、変更履歴（理由・外部要因）を残す。
3. **取り込み（intake）**: メール文面・議事録・口頭メモから、タスク／日程変更／待ち先を抽出し、登録案にする。承認後に反映する。
4. **今日の計画（daily-planner）**: MCP 経由で当日・当週の会議予定を取得し（未接続なら、スケジュール画面で会議を手入力する）、空き時間を算出する。取得した会議のうち、利用者が「参加しない」にしたものと、手入力した会議は、取得のたびに上書き・削除しない。未完了タスクを優先基準で並べ、理由付きで提案する。
5. **作業枠の配置と実績の記録**（会議の手動更新を含む）: 提案を見ながら、**自分で**画面上のカレンダーに作業枠を置く（プロット）。1つのタスクは何度でも、複数の枠に分けて置ける。未来の枠は「予定」、過ぎた枠は「実績」になる。見積時間は持たない。
6. **共有**: コマンド1つで、HTML と PDF のレポートを出力する。

### タスクが持つ情報
- 必須: 件名、プロジェクト、期限、状態、メモ。
- 関係: 先行タスク（依存関係）、待ち先（ベンダー／社内部署）。
- 任意: 重要度（利用者が付ける。未入力は「中」★）、開始日（**先行タスクがない場合だけ**指定できる。未入力なら期限の1点で表示★。先行タスクがある場合は、先行タスクの期限の最大値から自動で決まり、指定できない）。
- 作業枠（セッション）: タスクごとに複数。日付・開始・終了・種別（予定／実績）。タスクを `Done` にした日は完了日として記録する★。
- プロジェクト: 件名・種別・状態・**開始日（必須）**・期限・マイルストーン（名前と日付、複数）。開始日は期限以前。

### 予定管理と実績管理
- **プロジェクト画面は予定管理**: 計画（開始日・期限・先行・マイルストーン）を持ち、直す。
- **スケジュール画面は実績管理**: 置いた作業枠が、予定（未来）と実績（過去）になる。過ぎた予定の枠は「未確認」と表示し、「実績にする」で確定する（実際の時間と違うときは、枠をドラッグして時間を直してから確定する）。過去の日に新しく枠を置いたときは、実績として記録する。
- **作業枠と実績は時間の記録だけで、タスクの状態は自動では変わらない**（枠を置いても、実績にしても、To Do／In Progress／Done は変更されない。状態は利用者がリストなどで変える。完了日 `doneAt` は、利用者が `Done` にしたときだけ記録する）。
- 実績時間はタスクごと・プロジェクトごとに、実績枠の合計で出す。見積時間は持たないため、予実の差は工数ではなく**日付**で見る（計画のバーと、実績の線）。

### 状態の種類★
- **タスク（英語表記）**: `To Do`★／`In Progress`／`Waiting`／`Done`／`Cancelled`。`Waiting` は待ち先（ベンダー・社内部署）の回答や納品待ちで、自分では進められない状態。JSON の値・画面表示・レポートとも同じ英語表記とする。
- **プロジェクト**: 計画中／進行中／保留／完了／中止。
- **遅延・リスクは状態にせず、自動判定して表示する**: タスクは「期限超過」、プロジェクトは「期限超過のタスクがある」`Waiting` が長期化しているときにバッジを付ける。状態の入力を増やさず、更新漏れによる表示のずれを避けるため。
- 進捗率は、`Done` のタスク数 ÷（`Cancelled` を除く全タスク数）。

### 今日のタスクの優先基準（理由を必ず併記）
期限の近さ／他タスクの待ちを解消するもの（後続を止めている）／外部への催促・回答待ちの連絡／重要度（任意）。※「空き時間の長さへの適合」は見積時間を持たないため対象外。

**優先順位の算出（確定）**
- 対象: `Done`／`Cancelled` 以外のタスク。先行タスクが未完了のものは着手できないため除く。`Waiting` のタスクは「催促・確認」の行動として出す（期限を過ぎていれば「催促」、そうでなければ「確認」）。
- 点数: 期限超過 +100／期限まで14日以内は「(14 − 日数) × 3」（超過した分も加算）／そのタスクを先行とする未完了タスク（推移的）1件ごとに +10／重要度（高 +12、中・未設定 +4、低 0）／`Waiting` +15。
- 点数の高い順に並べ、同点は期限の早い順→ID順。各行に、期限・止めている後続の件数・重要度・待ち先と待ち日数などの理由を表示する。プロジェクト画面は上位4件、スケジュール画面は全件を出す。

### 画面
画面は **「プロジェクト」と「スケジュール」の2つ**。どちらも画面幅に合わせて幅が変わり（スケジュールのカレンダーは、**画面の高さに合わせて縦の長さも変わる**。9:00〜18:00 が画面に収まるよう、最小340px・最大1000px）（PC の広い画面から、スマートフォン幅まで）、ページ全体は横スクロールしない（ガントだけがその中で横スクロールする）★。

- **プロジェクト**（旧「全体俯瞰」を統合）: 上部で「すべて／個別のプロジェクト」を絞り込み、「ガント／リスト」を切り替える。右側に「今日の優先」（上位4件と理由）を置く。
  - **ガント**: 「すべて」は、全プロジェクトのガントチャートを**共通の時間軸で縦に並べる**。各プロジェクトの見出しに、種別・状態・期間（開始日〜期限、か月数）・進捗率★（完了タスク数／全タスク数）・実績時間・遅延を付け、先頭に全体バー（プロジェクトの開始日〜期限、進捗つき）を置く。各タスクの行は、計画のバー（開始〜期限）の下に**実績の線**（最初の実績の日〜完了日、作業中は今日まで）を重ねる。マイルストーンは、各プロジェクトの先頭に専用の行を設け、◆と**名前・日付**を表示し、その日付にプロジェクトの全行を貫く点線を引く（近接するときは名前を2段に分ける）。個別を選ぶと、そのプロジェクトだけを表示する。
  - **表示幅への追従と長期対応★**: ガントは、選んだ「表示期間」（1か月／3か月／6か月／1年／全期間、既定は6か月）が画面幅いっぱいに収まるよう、1日あたりの幅を自動で決める。1年以上のプロジェクトが多いため、期間より長い部分は横スクロールで見る。目盛りは表示期間に応じて切り替わる（**1か月は1日単位**で日付と曜日を表示し、土日を薄く着色、今日を赤で強調。3か月は週、6か月・1年は月、全期間が長いときは四半期）。左のタスク名の列と各プロジェクトの見出しは固定。年の境目は強調する。開いたときは今日の位置へ移動し、「今日へ移動」で戻れる。「完了を隠す」で Done のタスクを非表示にできる。
  - **ガント上の編集★**: ガントから直接、日付を変える（1日単位）。先行のないタスクのバーは、ドラッグで移動、左端で開始日、右端で期限を変えられる。先行のあるタスクは開始日が先行から決まるため、右端（期限）だけ動かせる。プロジェクトの全体バーは両端で開始日・期限を、マイルストーン（◆）はドラッグで日付を変えられる。後続タスクの期限より後ろへ動かしたときは警告を出し、日程の見直しは replan に任せる。各プロジェクトの末尾の入力欄に名前を入れて Enter でタスクを追加できる（期限は7日後、バーをドラッグして日程を決める）。各タスクの行の「×」で削除でき、後続タスクがあれば警告して確認する。**タスク名を押すと、リスト表示の該当タスクの行へ移動する**（件名などの修正はリストで行う）。
  - **リスト（編集）**: プロジェクトの状態・開始日・期限、各タスクの件名・状態・開始日（先行がないタスクのみ）・期限・先行・待ち先をその場で編集でき、タスクを追加・削除できる。先行があるタスクの開始日は「先行から」と表示する（編集不可）。各タスクの実績（時間・初回の作業日・回数）を読み取り専用で表示する。**マイルストーン**（名前と日付）の追加・変更・削除ができる。日程変更の履歴（下記）も表示する。ガントのタスク名から移動してきたときは、該当の行を強調して件名にカーソルを置く★。狭い画面では、1タスクを1枚のカードとして縦に並べる★。
- **スケジュール**（旧「週間」「1日」を統合）: 「週／日」を切り替え、「←／→／今日」で移動する。会議予定（時間枠）と、置いた作業枠（予定は水色、実績は緑、未確認は点線）を同じカレンダーに表示し、空き時間と実績時間が分かる。週表示の日付を押すと、その日の日表示に切り替わる。右側に「今日の優先」（全件と理由）を置く。
  - **ドラッグ＆ドロップによる配置**: 優先タスクを、週表示・日表示のどちらでもカレンダーへドラッグして作業枠を置く（15分刻み・長さ1時間★）。**同じタスクを何度でも置ける**。置いた枠もドラッグで移動でき、別の日へも動かせる。日表示では枠の下端をドラッグして終了時刻（実際に作業した時間）を直せる★。枠には「実績にする」ボタン（過ぎた予定のみ）があり、過ぎた未確認の枠は「すべて実績にする」でまとめて確定できる。**間違えたときは、スケジュール上の枠をクリックして選び、「枠を削除」ボタンか Delete キーで削除し、置き直す。選択は、枠や会議の外（欄外）をクリックするか Esc キーで外れる**（予定・実績のどちらも削除できる。「元に戻す」機能は設けない）★。実績の時間は、枠のドラッグ（移動）と下端のドラッグ（終了時刻）でいつでも直せる。画面の下部に**色の凡例**（会議は紫、予定は青緑、実績は緑、未確認は橙の点線で、互いに区別できる色にする）（会議・予定・実績・未確認・選択中、日表示は空き時間・現在時刻も）を表示する★。他の枠と重なる場合と土日は拒否し、会議と重なる場合は警告つきで許可する★。キーボード操作用に、日表示で「タスクを選んで空き枠を押す」方法も残す。
- **編集**: タスクの追加・削除、状態・期限・重要度・先行・待ち先・メモの変更、プロジェクトの状態・期限の変更。プロジェクトの追加・削除も可。先行になっているタスクの削除は警告を出し、承認後に参照を外す。先行の追加では、循環になる候補を出さない★。状態を `Waiting` にしたときは待ち先を入力させる★。

### 会議の管理（手動更新と不参加）
- 会議（`events`）は、**MCP で取得したもの**（`source: "mcp"`）と**手入力したもの**（`source: "manual"`）の2種類。スケジュール画面の「＋ 会議を追加」で、件名・日付・開始・終了を入力して追加できる（MCP が未接続でも使える）。
- 手入力の会議は、件名・日付・時間・「参加しない」を編集でき、削除できる。
- MCP で取得した会議は、件名・日付・時間は取得内容が正のため変更できない。**出席しない会議は「参加しない」にできる**（MCP が接続できていても参加しない会議があるため）。「参加しない」の会議は、薄く表示して空き時間として扱い、そこへ作業枠を置ける。削除は不可（削除しても次の取得で戻るため）。
- daily-planner が取得内容を反映するときは、取得対象の期間について、MCP 由来の会議だけを追加・更新・削除（取得結果から消えた会議）し、`skip` の値は保持する。手入力の会議には触れない。
- **手入力の会議は、カレンダー上でドラッグして移動（別の日へも）、下端のドラッグで長さを変えられる**（15分刻み、タスクの枠と同じ操作）。MCP 由来の会議は、時間を変えられない（「参加しない」のみ）。
- 勤務時間（9:00〜18:00）の外にある会議は、カレンダーには表示しない（範囲に入る部分だけ表示する）。

### 日程変更の履歴
日程が動いたときに「いつ・どのタスクが・何日動いたか・なぜか」を残す記録（旧称「日程が動いた理由」）。replan が日程を更新するときに自動で追記し、画面からも見られる。項目は、日付・対象タスク・動いた日数・理由（文章）・原因（ベンダー／社内／自分／その他）。メンバーへの報告で「なぜ遅れたか」を説明するため、レポートにも載せる★。**記録するのは replan が日程を更新したときだけ**で、ガントのドラッグやリストでの日付変更では記録しない（確認済み）。

### デザインの決め方
実装前に、ダッシュボード（プロジェクト・スケジュール）のデザイン案を **Artifact（ダミーデータの見た目確認用）** で作り、見て決める。確定後に実装へ反映する（`frontend-design` を使用）。実データは載せない★。

### レポート（HTML／PDF）
全プロジェクトの一覧、プロジェクト別の詳細、今週の予定（週間スケジュール）。会議は時間枠のみを表示し、件名は載せない★（設定で変更可）。

## 受入条件

1. 複数のプロジェクトとタスクを JSON に登録し、ダッシュボードで一覧・詳細を表示できる。
2. ダッシュボードで、タスクの件名・状態・期限・重要度・先行・待ち先・メモの変更、プロジェクトの状態・開始日・期限の変更、マイルストーンの追加・変更・削除、タスク／プロジェクトの追加・削除ができ、JSON に保存される。保存に失敗したときは、画面に明示する。
3. ガント上で、先行のないタスクのバーの移動・両端のドラッグ、先行のあるタスクの期限（右端）のドラッグ、プロジェクトの全体バーの両端のドラッグ、マイルストーンのドラッグで日付を変更でき、JSON に保存される。先行のあるタスクの開始日は変更できない。ガントの入力欄からタスクを追加でき、「×」で（確認のうえ）削除でき、タスク名を押すとリストの該当行に移動する。
4. Claude Code が JSON を更新した後、「更新」ボタンで画面に反映される。
5. replan に「ベンダーXの納品が2週間遅れた」と伝えると、影響を受けるタスクの一覧と日程変更案が理由付きで出る。承認後に JSON と変更履歴が更新される。承認なしでは更新されない。
6. intake にメール文面を渡すと、タスク／日程変更の登録案が出る。承認後に反映される。
7. MCP が接続されている場合、daily-planner が当日・当週の会議予定を取得して空き時間を算出し、優先基準に沿ったタスク順と理由を提示できる。未接続の場合は、スケジュール画面で会議を手入力して追加・編集・削除でき、同じ結果になる。MCP で取得した会議を「参加しない」にすると、空き時間として扱われ、次の取得でもその設定が保持される。
8. スケジュール画面で、週／日を切り替えて会議と作業枠を同じカレンダー上で見られる。利用者が1つのタスクの枠を複数置き、週表示・日表示のドラッグ＆ドロップで配置・移動し（別の日へも）、日表示で終了時刻を直し、解除できる。土日への配置と、他の枠との重なりは拒否される。
9. 作業枠を置く・実績にする・解除する操作で、タスクの状態は変わらない。選択した枠を削除できる（予定・実績とも）。欄外をクリックするか Esc で選択が外れ、削除ボタンが無効に戻る。画面に色の凡例が表示される。未来の枠は予定、過去の枠は実績として扱われる。過ぎた予定の枠は「未確認」と表示され、「実績にする」で確定できる。過去の日に置いた枠は実績になる。タスクごと・プロジェクトごとの実績時間が、実績枠の合計と一致する。
10. プロジェクト画面で、18か月規模のプロジェクトでも、表示期間（1か月／3か月／6か月／1年／全期間）を選ぶとその期間が画面幅に収まり、目盛りが正しく表示され、今日の位置から開く。「すべて」で全プロジェクトのガントが共通の時間軸で縦に並び、個別に絞り込むと1件のガントが表示され、リスト／ガントを切り替えられる。各タスクの行に、計画のバーと実績の線が表示され、マイルストーンが名前・日付つきの◆と点線で表示される。表示期間「1か月」では、1日単位の目盛り（日付・曜日）が表示される。
11. 画面の高さを変えると、スケジュールのカレンダーの縦の長さが追従し（最小340px）、画面幅を PC（約1700px）からスマートフォン（約400px）まで変えても、ページ全体が横スクロールせず、リストはカード表示に切り替わる。
12. レポートのコマンドで HTML と PDF が出力され、全体一覧・プロジェクト別詳細・今週の予定が含まれる。
13. デザインは、Artifact での見た目確認を経て利用者が承認したものになっている。
14. README に、導入手順（MCP の用意、ダッシュボードを開いて JSON を選ぶ手順）、各サブエージェントの使い方、レポートの出力方法が書かれている。
15. 論理を持つ部分（優先順位付け、影響範囲の算出、進捗率）は、自動テストで検証される。

## 非目標

- ローカルサーバー／常駐プロセス／SQLite の利用。
- MCP の同梱（接続設定は利用者が行う）。
- Confluence への自動投稿（共有は HTML／PDF のみ）。Confluence からのデータ移行。
- 見積時間（工数）の管理、空き時間への自動割当、見積と実績の工数差の分析。
- 複数ユーザーの同時編集、アカウント管理、アクセス制御。
- レポート生成用のサブエージェント（スクリプトで行う）。
- プロジェクト種別のテンプレート、通知／リマインド機能★。
- Outlook への書き込み（予定の作成・変更）★。

## リスク

1. **入力の手間で更新が止まる**: 対策は、Claude Code への自然文入力と intake、重要度などを任意項目にすること。
2. **画面編集の保存が不安定**: File System Access API は Edge/Chrome のみで、許可の再確認が必要。`file://` で動作するかは**未検証**。MVP 最初の試作で確認し、不可の場合は「画面は閲覧専用、更新は Claude Code」に切り替える（Q16-A）。
3. **Claude Code と画面の同時更新による衝突**: 最後の保存が勝つ。保存前に JSON の更新時刻を確認し、変更されていたら警告する★。
4. **Outlook 用 MCP の有無が不明**: 現在確認できた予定表系 MCP は Google Calendar のみ。未接続でも動くよう、手入力のフォールバックを持つ。
5. **会社 PC の制約**（ツール導入・Claude Code の利用可否）は未確認。
6. **スケジュール変更の影響範囲は先行関係の入力品質に依存**する。先行関係が未入力のタスクは、影響範囲に含まれない。
