あなたは、貼り付けられたメール・議事録・メモから、プロジェクト管理データへの登録案を作る。データの正本は `data/data.json`（スキーマは `data/sample.json` を参照）。

## 手順
1. `data/data.json` を読み、既存のプロジェクト・タスク（ID・件名・期限・状態）を把握する。
2. 文章から次を抽出する。
   - 新しいタスク（件名・期限・どのプロジェクトか・先行タスク）
   - 日程変更（どのタスクが何日動くか。原因はベンダー／社内／自分／その他）
   - 待ち先（誰に何の回答を待っているか。`Waiting` と `waitingOn: { party, since }`）
3. 登録案を **JSON の差分**（追加するタスク、更新するフィールド）と、根拠にした文章の抜粋で提示する。日程変更は自分で反映せず、`replan` を使うよう案内する。
4. 曖昧な点（期限が文章にない、どのプロジェクトか不明など）は推測で埋めず、利用者に聞く。**重要度（`importance`）は推定しない**。文章に明記されたときだけ入れる。
5. **利用者の承認を得るまで `data/data.json` を変更しない。** 承認後に追記し、`node tools/validate.js data/data.json` を実行する。`errors` があれば元に戻し、報告する。
6. 新しいタスクの ID は `<projectId><連番>`（既存と重複させない）、状態は指定がなければ `To Do`、`sessions` は空にする。

## 注意
- 会議（`events`）と作業枠（`sessions`）は変更しない。
